# Card Play Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the 3-actions-per-turn player turn with a hand of free action cards: draw 1 per turn, play at most 1, keep the rest.

**Architecture:** A pure `game/logic/cards.js` rolls cards with the injected RNG. `GameState` gains `hand`, `cardPlayedThisTurn`, `playCard()` and `cardPlayable()`. Its build, upgrade, sell and bell helpers lose their cost, action and once-per-level checks. Bots play cards. In the UI the side panel's BuildMenu becomes a HandPanel, the scene gets a "pending card" targeting mode, and the TowerPanel loses its buttons.

**Tech Stack:** Native ES modules, Phaser 3.90 (scenes only), `node --test` (run from `tower-defence/`: `npm test`).

**Spec:** `docs/superpowers/specs/2026-11-25-cards-design.md`

## Global Constraints

- No build step, no new dependencies. `game/logic/` stays free of Phaser and the DOM.
- No data model, DB, editor or Supabase changes. Weapon `cost` stays in the data and is ignored in play.
- One card per turn. Starting hand 3, draw 1 per later player turn, hand max 7.
- Draw weights: Build 55 %, Upgrade 30 %, Sell 10 %, Bell 5 %. If no level weapon has upgrades, Upgrade rolls become Build.
- The starting hand has at least 2 Build cards, with different weapons when the level has 2 or more weapons.
- The guests' turn rules are unchanged.
- Work stays on branch `cards`. Nothing is pushed without the author's say-so.

## Review Focus

1. **Card with no valid target selected** (e.g. Upgrade, then the only matching tower is gone). Esc, right-click or clicking the card again always cancels, and an invalid target click toasts a reason and keeps the card in the hand. Test in Task 1: a failed `playCard` leaves `hand` and `cardPlayedThisTurn` unchanged.
2. **Full hand.** At 7 cards no draw happens, and no `draw` event is emitted. Test in Task 1.
3. **Level with a single weapon or no upgradable weapon.** The starting hand is still valid, and no Upgrade cards are rolled. Test in Task 1.
4. **Game ends during the guests' turn.** No card is drawn after `won` or `lost`. Test in Task 1.
5. **Bell card with no guests present.** It is not playable (`no-target`), so it isn't wasted. Test in Task 1.

### Task 1: Card engine

**Files:**
- Create: `tower-defence/game/logic/cards.js`
- Modify: `tower-defence/game/logic/state.js`
- Test: `tower-defence/test/cards.test.js` (new), `tower-defence/test/state.test.js` (adapt)

**Interfaces:**
- Produces, in `cards.js`:
  - `CARD_KINDS = ['build', 'upgrade', 'sell', 'bell']`
  - `HAND_START = 3`, `HAND_MAX = 7`
  - `CARD_WEIGHTS = { build: 0.55, upgrade: 0.30, sell: 0.10, bell: 0.05 }`
  - `rollCard(rng, weapons) -> { kind, weaponId? }`. Here `weapons` is the level's weapon defs. `weaponId` is set only for `build` and `upgrade`. It rolls the kind by cumulative weights using one `rng()` value, then the weapon with `floor(rng() * n)`. For `upgrade`, it picks only from weapons with a non-empty `upgrades`; if there are none, the kind becomes `build`.
  - `startingHand(rng, weapons) -> card[]`: 3 cards. Slots 0 and 1 are Build cards with distinct weapons when possible; slot 2 is `rollCard`.
  - `cardTitle(card, weaponDefs) -> string`: "Build Café", "Upgrade Café", "Sell a weapon", "Ring the bell".
- Produces, in `GameState`:
  - `hand: Array<{ id: number, kind, weaponId? }>`, with ids from `nextCardId`.
  - `cardPlayedThisTurn: boolean`.
  - `playCard(cardId, target?) -> { ok: true, events?: [], refund? } | { ok: false, reason }`. `target` is `{ x, y }` for build and `{ towerId }` for upgrade and sell. Bell takes no target and returns `ringBell`'s `events`.
  - Reasons are checked in this order: `game-over`, `card-played`, `unknown-card`, then the kind-specific ones:
    - build: `not-buildable`, or `no-target` when the target is missing
    - upgrade: `no-target`, `wrong-weapon` (the tower's weapon differs from the card's), `max-tier`
    - sell: `no-target`
    - bell: `no-target` when there are no guests
  - On success, the card is removed from `hand` and `cardPlayedThisTurn = true`. On failure, nothing changes.
  - `cardPlayable(card) -> boolean`: false when a card was already played this turn or the game is over. Otherwise, per kind:
    - build: some tile is buildable
    - upgrade: there is a tower of that weapon below max tier
    - sell: there is at least one tower
    - bell: there are guests present
  - `placeTower(x, y, weaponId)`, `upgradeTower(towerId)`, `sellTower(towerId)` and `ringBell()` stay public. Tests use them for setup. They lose the cost check, the `no-actions` check and the once-per-level bell, and no longer touch `corks` when spending. `spent` still accumulates the data cost, so the sell refund stays 50 % of spent. They keep `game-over`, `not-in-level`, `not-buildable`, `unknown` and `max-tier`.
  - Removed: `actionsLeft`, `ACTIONS_PER_TURN`, `ACTION_BONUS`, the `bonus` event, `bellUsed` and `actionRefusal`.
  - The constructor sets `hand = startingHand(rng, levelWeapons)`. The starting hand is rolled before any quote rolls.
  - At the end of `finishTurn()`, when the game isn't over and `hand.length < HAND_MAX`, a card is rolled and pushed to `hand`, and a `draw` event `{ type: 'draw', card }` is emitted. In every case, `cardPlayedThisTurn` resets to `false`.

**Interfaces:**
- Consumes: `state.hand`, `state.playCard`, `state.cardPlayable` (Task 1).
- Produces: `playSensibly(state, { only })` and `playMixed(state, { only })`. Each plays at most one card per call; `runGame` is unchanged in signature and return shape. `weaponScore(w)` becomes `damage × fireRate` (the cost term is dropped; damage-0 weapons keep the effect formula). `damageScore` and `supportScore` drop `/ cost` too.

- [ ] **Step 1: Rewrite the bots.**

  - **Mixed:** apply its 2-damage : 1-support rule to the Build cards it holds. If it wants a support and holds one, it builds it with `supportTileFor`. Otherwise it builds the best damage card, then upgrades, as the sensible bot does.
  - Update the header comment.
